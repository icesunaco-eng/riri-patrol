# りり見回りプログラム v0.2

要件第2.2版と、たかむねから届いた9項目の修正依頼を反映した実装・模擬試験用プロジェクトです。りりのMacへの設定、launchd登録、実トークンでの運転はしていません。

## いま試せること

Python 3.11以上、標準ライブラリだけで動きます。追加アプリの導入は不要です。

```bash
python3 -m unittest discover -s tests -v
python3 scripts/demo.py
```

試験とデモは架空データで動き、実際のSlack・Notion・Ollamaには接続しません。試験の全結果は `docs/test-results.txt`、確認内容は `docs/verification.md` を参照してください。デモは.envを読まず、5回の練習を行います。生成物は一時フォルダに残し、自動削除しません。

## 固定プログラムが行うこと

- STOP、二重起動ロック、4分以内の終了、Slackボットの本人確認を先に行います。
- 未着手の依頼を古い順に処理します。1回の指示は最大1件、指示・報告・通知を合わせて最大4件です。
- みにへの伝言、りり自身宛ての除外、5人の完了報告、全宛先完了時の状態更新を扱います。
- 出来事をローカルに保持し、3時間ごとにNotionの指定9列表へ新しい順で追記します。
- Qwen3.6に任せるのは末尾の挨拶の調整だけです。依頼内容・宛先・手順・期限は固定し、ツールは渡しません。不正な出力や接続失敗時は固定文面に戻します。
- 禁止ユーザー `U0C5V11S37X` として投稿しません。ボットトークンと、.envに明示された本人確認IDが一致した場合だけ送信できます。

## 設定と練習モード

秘密の値をREADME・チャット・GitHubへ書かないでください。`.env.example` は秘密と本人確認IDが空の見本です。本物の.envは配備承認後に対象Macだけへ置きます。

すべての設定を.envだけから読みます。ターミナルの環境変数による本番化・トークンの差し替えはできません。`RIRI_MODE=live` と本人が.envに書いたときだけ本番です。未設定・誤記は練習です。本番の見回り開始時は `本番（.envより）` と記録します。

`EXPECTED_SLACK_BOT_ID` と `EXPECTED_SLACK_USER_ID` が未設定・空欄なら、練習でも停止します。コード内の固定IDへは戻しません。

```bash
# 配備承認後の操作説明。読み取りは行いますが、Slack・Notionへは書きません。
python3 patrol.py --dry-run --verbose

# 状態の概要だけ。通信・状態変更なし（.envの設定は必要）。
python3 patrol.py --status

# ログ追記を待たず処理。練習なら検証・記録だけ。
python3 patrol.py --flush-log
```

練習と本番は同じ書き込み検証を通り、練習では最後の外部書き込みだけ止めます。Slack文面・チャンネルID、Notionの書き込み直前の再読込・本文・編集版・状態遷移、ログ表の列名を確認します。練習と本番の状態ファイルは別です。

練習はNotionを変更しないため、未着手のままの依頼を直接「完了」にする練習も拒否します。完了更新を試す模擬データは「対応中」で用意します。デモもそのように架空データを切り替えています。

## STOP

プロジェクト内の `STOP` ファイルで止まります。`STOP_FILE` で別の場所も指定できます。停止中は状態を変更せず動作ログに1行だけ残します。実行途中も各通信の直前に確認します。すでに送った通信を取り消すことはできません。

## Slack投稿が保留になったとき

投稿には `rp:英数字` の照合用の印が1行付きます。履歴はHTMLエスケープを戻し、同じボット・同じ印の行・有効なtsを確認します。履歴を最後まで読めない場合や一致がない場合は自動再投稿せず保留にします。送信直後のtsは状態ファイルへ保存します。

一度heldになった依頼は、後から履歴に現れても自動解除しません。たかむねが履歴を確認して、次のいずれかを実行します。

```bash
# 実際に出ていることを確認済み。再投稿しない。
python3 patrol.py --resolve '依頼ID' posted

# 実際に出ていないことを確認済み。次の見回りで一度だけ投稿を許可。
python3 patrol.py --resolve '依頼ID' not_posted
```

この操作は通常の見回りと同じロックを取り、Slack投稿結果がheldの依頼だけを変更し、変更をローカルログへ残します。通信はしません。not_postedは「一度だけ許可」の印を付けます。次回の投稿が成功したら印を消し、繰り返し投稿しません。元のNotion状態が対応中でも許可されますが、本文変更・完了・削除等は再検証して止めます。再び結果不明なら再度heldです。

postedによる手動確認では、確認できていないtsを作りません。練習状態を解決する場合は `--dry-run` も付けてください。STOP中はresolveもしません。状態ファイルを削除してやり直すと重複投稿の危険があるため、削除しないでください。

Notion競合の保留、一般通知の保留、Notionログ追記の保留は、このSlack指示用resolveの対象外です。履歴・監査ログを確認し、必要な復旧を別途判断します。保留中は誤って「直りました」と知らせません。

## Notionの同時編集への備え

書き込み前のlast_edited_timeと本文を記録し、更新直前に再読込、更新直後にも再読込して比較します。本文や編集版の競合、更新結果や後の読み取りが不明な場合はheldにし、自動で上書き修復・次の処理へ継続しません。

前後本文は `logs/notion-audit.jsonl` へ伏字付き・所有者だけが読める権限で保存します。これは復旧判断用で、Slack・Notion・GitHubへ送信しません。本文には私的な情報が含まれ得るのでローカルで保護してください。

Notion APIには条件付き更新（CAS）がないため、直前の読取とPATCHのすき間に行われた編集をこちらが上書きする競合は、完全には防止・検知できません。本番前に同時編集を避ける運用を確認してください。

## ログの容量通知

7日／30日の年齢判定は使いません。logsとstateの通常ファイルの合計が既定50 MiB（52,428,800バイト）を超えたら、3時間ごとのまとめ報告で整理するか聞きます。前回の通知成功から7日以上空け、未送信・保留の同じ通知は重ねません。1回4件の投稿上限に数えます。

閾値は.envの `LOG_SIZE_NOTICE_BYTES` で指定できます。ログ・状態・練習記録・監査ログを自動削除する処理はありません。本人が確認して整理します。

## 異常時の停止

Python 3.11より古いと、通常処理の読込前に固定の画面通知を試みて終了します。想定外エラーも最後で受け止め、秘密を伏せたローカル記録と固定の画面通知を行います。通知はmacOSのosascriptを使い、この環境では実機表示は未確認です。画面通知に例外本文や秘密は入れません。

## 未検証・配備しない範囲

実際のSlack/Notionトークン・権限・投稿、実Qwen3.6、りりのMacのPython・画面通知・5分運転は未検証です。模擬試験合格は本番接続の合格を意味しません。

launchdは未登録テンプレートだけです。Python欄は未設定と分かる絶対パス `/__UNCONFIGURED_PYTHON_311_OR_NEWER_ABSOLUTE_PATH__` にしてあり、そのまま実行できません。対象Macの実在するPython 3.11以上のフルパスは未確認です。配備承認後に確認して置き換えます。install/uninstallスクリプトは説明を出して終了し、登録・解除をしません。

モデル変更後にたかむねの承認を得てから、旧Hermesスケジュール、依頼ページの状態、宛先欄、必要権限、トークン、Pythonを別の配備手順で確認します。
