## 文字数と予算

従来の「材料1500＋固定案内72＝1572」を「材料3000＋固定案内72＝3072」へ拡張する。材料とは本文の値、必須ヘッダー（宛先、依頼ID、依頼した子、報告先URL、項目名など）、従来の固定文・挨拶・区切り改行を合わせた配送用canonicalである。ヘッダー等がH文字なら本文の残り枠は3000−H文字。本文だけで3000文字を別枠保証する仕様ではない。

追加の作業場所URL固定案内はコードが生成する正確な71文字＋改行1文字だけを別枠にする。本文内の同じ文は材料枠を消費する。上限超過では送信前に保留し、短縮・切捨て・分割で通さない。

Python `len(str)`と同じUnicode code point数で数える。`😀`は1（UTF-16では2）、`❤️`は2、`e\u0301`は2、`👨‍👩‍👧‍👦`は7（UTF-16では11）。見た目の書記素数やUTF-8 byte数を使わず、NFC/NFKC正規化もしない。UTF-8で表現できない孤立サロゲートは安全検査で拒否する。

現行どおりCRLF/CRをLFへ統一し、値の中の改行に2空白インデントを加え、`& < >`をSlack用にescapeした後の配送表現を数える。LFは1、空白は各1、`&amp;`は5。元Notion本文とsnapshotは書き換えない。HTML実体や改行を使って予算を回避できず、normalize/escapeした全文が送られる。

Slackの照合印（改行＋rp:24hex＝28文字）、既存GDMメンション、承認済み代理投稿ラベルは配送装飾として別枠。模擬HTTPまで通した完成文が4000文字未満であることを確認する。[Slackのchat.postMessage仕様](https://docs.slack.dev/reference/methods/chat.postMessage/)は4000文字を推奨し、長文が複数メッセージに分かれる可能性を示している。新しい分割処理やスニペット送信は追加しない。

## 経路と安全性

`compose.instruction`が唯一のcanonical生成・文字数検査を担う。prepare/send、Slack指示、GDM複製、local起動入力、まむ受付で同じ本文を使う。まむ32KiB、local2MiBのbyte上限は変更不要。案件ページ欄の独立1500文字安全上限、報告batch2800文字の既存条件は別用途であり保持する。

LLMは従来の800token・90秒・最大2回を保持する。旧総上限1572文字を超えるcanonicalはLLMへ渡さず決まった型を使い、長文コピーによる欠落や余計なモデル負荷を避ける。短文は従来経路を維持し、長短ともvalidatorは全行・値・順序・案内の完全一致を要求する。挨拶だけ既存の選択肢を許容する。

入力hash、送信前永続化、同ID/内容重複防止、不明ID隔離、状態version2と各状態遷移、STOP、過去done、結果不明時の再送禁止を保持する。上限を広げただけでは旧unsafe_content保留のdigestは変わらず解除しない。過去依頼やりり→みにの保留連携テストを再開しない。

## 保存・適用・戻し

現行Macは`3162bd5`で、mainには別案件を含む既存6commitが未統合。この案件は同版から分けたfeatureを専用release系統へマージし、mainやみき登録ブランチを今回の範囲で更新しない。以前のPRも勝手にマージしない。

1. 適用直前に現行HEAD・全追跡差分・STOP・plistの300秒条件・worker/lockを再確認する。他案件差分や予期しない版があれば停止して再統合する。
2. 既存STOPがないことを確認して作業用STOPを作る。既存巡回は自然終了を待ち、patrol/mamu/localのlockを確認する。無関係なプロセスをkillしない。
3. 最新state/logsと旧追跡コードをworkspace内のprivate保全先へ保存する。.envの値は複製・表示せず、.env/plistのhashと権限だけを比較する。
4. lockを保持し、検査済みreleaseへff-only更新する。state/logsのhash不変、state読み込み、versionとmodeを通信なしで確認する。成功後、今回作ったSTOPだけを外す。plistや頻度は変更しない。
5. 既存の通常巡回を自然に待ち、last_run_at、last_error、launchd終了、既postedの証拠とURL baseline保持を確認する。新規実配送の有無は別記録にする。

戻す場合は同じSTOP/自然終了/lock/保全を行い、追跡コードだけ旧commit`3162bd5`へ戻す。既存state・logsを旧バックアップで上書きしない。新しい既posted、done、結果不明、入力hashを失う復元は禁止。上限を戻しても既送信を取り消したり旧保留を再送したりしない。失敗時はSTOPを残し、未適用/部分適用/未再開を具体的に報告する。
