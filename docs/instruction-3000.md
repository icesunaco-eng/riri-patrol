## 原文と配送表現の予算

| 対象 | 上限と計数 |
| --- | --- |
| 本文 | やること・手順・使うもの・期待する結果・やってはいけないことの原文値合計3000 code points |
| 可変ヘッダー | ID、宛先、依頼した子、期限、GitHub/案件ページ、報告先URL、全項目名、未記入欄の「なし」、従来固定文、区切り改行、挨拶の配送表現合計1500 code points |
| 固定URL案内 | コード生成の71文字＋区切り改行1文字＝72 code points |
| 本文の配送表現 | 原文の最大5倍（amp形式escape）。3000×5＝15000 code points |
| canonical | 本文配送表現15000＋ヘッダー1500＋案内72＝最大16572 code points |
| 配送装飾 | 既存照合印28文字、GDMメンション、代理投稿ラベルを合わせ別枠256 code points以内 |
| 全配送表現 | 最大16828 code points。上限超過は送信前停止 |

本文に同じ固定案内を記入しても原文3000枠へ数える。未記入欄にコードが補う「なし」はヘッダー枠で数える。ヘッダーが長くても本文3000枠は減らさない。ヘッダー1501字はヘッダー過大として停止する。本文3001字は本文過大として停止し、短縮・切捨て・別投稿へ分割して通さない。

原文計数はPython `len(str)`相当のUnicode code point数。`😀`は1（UTF-16では2）、`❤️`は2、`e\u0301`は2、`👨‍👩‍👧‍👦`は7（UTF-16では11）。LFは1、CRLFは2、CRは1。NFC/NFKC正規化なし。孤立サロゲートはUTF-8配送不能として拒否する。既存parserの欄抽出後の値を対象にする。

配送は従来どおりCRLF/CR→LF、改行後の2空白インデント、`& < >`のescapeを行うが、この増分を本文枠から引かない。原Notion本文とsnapshotは書き換えない。`compose.instruction_budget()`が本文原文・本文配送表現・ヘッダー・固定案内・canonicalの実測値を返し、生成と同じ検査を通る。

## 1回のSlack投稿に全文を保持

短文は既存の`text`投稿。配送文が3500 UTF-16 units超なら、[rich_text](https://docs.slack.dev/reference/block-kit/blocks/rich-text-block/)を1block・1sectionで送る。3000文字以下の複数text要素は同一section内で隣接し、追加の改行や別投稿を作らない。トップレベルの長文textを重ねず、Slackによる長文通常textの分割・切捨てに依存しない。1宛先につき1回の`chat.postMessage`。スニペット・ファイル化・要約を行わない。

text要素ではcanonicalの3種類のescapeを1層だけ戻し、文字をリテラルとして保持する。元からある文字列のHTML実体を勝手に深くdecodeしない。GDM先頭の許可済み1人だけを専用user要素にし、他の能動要素や任意メンションを作らない。送信前と認証済みuser投稿の境界の両方で安全検査を行う。

構造化投稿の成功返却では、block ID以外の許可した形から全文を復元し、表示表現が完全一致することを確認する。欠落・変更・切捨て/分割警告は配送完全性不明として既存heldへ隔離し、その場で照合印だけを見て成功へ変えず、自動再送しない。タイムアウトや再起動後の履歴照合も全文と送信者・宛先・照合印を照合する。本人トークンが後で空になっても、旧本人投稿の完全な証拠をbot履歴から確認できる。

## 全経路と安全性

prepare/send、Slack指示、GDM複製、local起動入力、まむ受付と配送証明は共通canonicalを用いる。LLMは従来の800token・90秒・最大2回を保持し、1572字超では呼ばず型全文を使う。validatorは全長で全行・値・順序・固定案内の一致を要求し、挨拶だけ既存選択肢を許容する。

Notionの[2000文字text要素制限](https://developers.notion.com/reference/request-limits)に対しては、2000 code pointsと2000 UTF-16 unitsの両方に収まる要素へ分ける。これは1つのコードブロックの内部表現であり、別依頼・別投稿へ分けない。状態更新では非状態文字・annotations・リンクを保持し、まむ受付のappendにも同じ要素分けを使う。

local2MiB、まむ32KiBのbyte上限は変更不要。案件ページ欄の独立1500文字安全上限、報告batch2800文字は別用途として保持する。入力hash、送信前永続化、同ID/内容重複防止、不明ID隔離、状態version2、STOP、旧done、結果不明時の再送禁止を維持する。上限拡張だけでは旧unsafe_contentのdigestは変わらず、保留を解除しない。
