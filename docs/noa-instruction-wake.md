## 動作

- 新しい原本 instruction を作成する時点で NOA_WAKE_ENABLED が true、宛先に「のあ」が含まれる場合のみ、既存 outbox 項目に任意の起動意図を保存します。
- 固定の指示部屋への原本が posted と確定してから、保存していた投稿本文（末尾 rp 印を含む）と検証済み permalink を既存 NoaClient に渡します。送信結果不明の原本、完了報告の中継、他のボット投稿は起動対象にしません。
- 意図は `instruction:{依頼ID}` に付属するため、同じ依頼IDの再投稿や再起動で起動を繰り返しません。呼出前に sending と時刻を fsync 保存し、中断・結果不明は held になります。生成した指示では429も自動再試行しません。STOP等で通信前と確定した例外だけは未送信として戻します。
- 既存の人間からの @のあ の受付は残し、1回の巡回で実際の fire 呼出は両経路の合計1回、1時間の合計は10回までです。
- OFF・練習モード・STOPでは起動しません。OFF中に作った原本へ後付けで意図を足しません。OFFまたは長い巡回停止後の再開で以前から待機していた意図を再生しません（同じ巡回中に作成または投稿確定した原本は保持し、未確定なら後の投稿確定を待ちます）。
- 本文に秘密情報が含まれた場合、他チャンネル、無効なリンクは送信前に止めます。実値は通知・ログに転記しません。

## 状態と確認

必須の新しい state キーや version の変更はありません。既存 outbox の任意項目 `noa_instruction_wake` に状態と試行時刻を保存します。旧stateにこの項目は不要で、旧原本は後から起動しません。旧版ローダーで追加項目を保持して読めることも試験しています。

`--status` の `noa_instruction_wakes` に依頼ID・状態・試行時刻・固定理由を表示します。held/rejected は巡回の held 判定と復旧待ちに反映しますが、送信済みのSlack原本を held に書き換えません。保留時は固定の確認通知を依頼IDにつき1件だけキューします。

自動再送はしません。既存の手動resolveはSlack/人間メンションのもので、既存 `--resolve noa` ではこの追加起動意図を扱いません。held/rejected が残る間は `recovery_unresolved` による復旧待ちも継続する運用制限があります。この追加起動意図に手動再送・削除による再試行機能はありません。held時は外部の実行結果を本人が確認する必要があります。状態ファイルを消したり、別IDで無条件に再依頼しないでください。旧版へ戻すと、この追加起動・状態表示自体は行いませんが追加記録は保持されます。
