# まむ・みきの受け口（agent lane）

設計：Notion「まむ・みき｜りり経由の依頼受付と完了報告 設計 v0.3」。既定はすべてオフです。

## 何をするか

- 宛先にまむ・みきが入った「未着手」の依頼（`local-run=` などの固定jobの印がないもの）は、Slackの指示部屋には流しません。
- 受け口がオンなら、`state/agent-lane/jobs/` に job を1件作り、「たかむねりりあいす」へ【受け渡し】を1回だけ投稿して、状態を「対応中」にします。
- 受け口がオフなら、状態は「未着手」のまま、「受け口が止まっているので保留」を1回だけ投稿します。
- 見回りのたびに1件ずつ、結果の回収 → 完了報告の代筆（その子の完了報告ページ、読み戻しで照合）→ 次の job の起動、をします。
- 起動するのは `~/mamu-AI/start-mamu-agent.sh` / `~/miki-AI/start-miki-agent.sh`。job は標準入力で渡し、環境変数は最小限（トークンなし）です。
- まむ・みきが Notion を読む・書く・ほかの子へ依頼を出すときは `python -m riri.agent_broker` を通ります。共通ルール・完了報告・依頼一覧・ログのページは書けません。

## .env の設定

| キー | 既定 | 意味 |
|---|---|---|
| `LOCAL_AGENT_MAMU` | false | まむの受け口 |
| `LOCAL_AGENT_MIKI` | false | みきの受け口 |
| `LOCAL_AGENT_TOOLS` | read | 使ってよい道具箱（カンマ区切り：read, write, run, github, notion, request）。read は常にオン |
| `LOCAL_AGENT_HOURLY` | 20 | 担当ごとの1時間の受付上限（1〜60） |
| `LOCAL_AGENT_DAILY` | 150 | 担当ごとの1日の受付上限（1〜500） |

オンにする順番は設計どおり：read → write,run → github,notion → request。段ごとにたかむねの OK をもらいます。

## 止まり方

- STOP があると起動しません（ブローカーも断ります）。
- 重いモデルが使用中・メモリ不足のときは5分あけて最大3回。だめなら「できなかった」の完了報告。
- 24時間始められなければ「できなかった」。実行は30分（りり側は35分）で打ち切り。
- 報告の書込み結果が分からないときは読み戻しだけにして、二重に書きません。
