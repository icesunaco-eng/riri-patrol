## 送信契約

新しい配送にだけ `dual-v2` policyを固定する。あいすを含まない指示と、既存outboxの送信者・本文・照合印は移行しない。
本人ユーザートークンが未設定・利用不可でも、ボット名義へ切り替えない。対象だけ待機する。

本人名義にも既存の自動代理投稿ラベルを付け、元依頼者と報告者を表示する。

完了報告の依頼元は受付snapshotを優先し、同じID・同じ原本、報告者が元宛先に含まれることを照合する。
IDのハート、報告者、本文中の名前から推測しない。原本不明・重複・内容不一致はその通知だけ照合待ちにする。
確認済み公式IDを使える子にはそのID、登録のない子には既存の文字 `@名前` を使い、本人への伝達待ちを区別する。
みに向けの既存手渡しを新しい連携試験に置き換えない。

## 認証・メンション設定

既存の `SLACK_REPORT_USER_TOKEN` と `ICE_MENTION_USER_ID` を利用する。秘密値をこの文書やコードへ転記しない。
追加任意設定 `SLACK_REQUESTER_MENTION_IDS` は「正式名→確認済みSlackユーザーID」のJSONオブジェクト。
省略時はあいすの既存登録だけを使い、他の子は文字宛先になる。既存のあいす設定との矛盾、未登録名、ID重複、
本人・りりIDとの混同、不正JSONを拒否する。設定値の書式が正しいことと、実際にその子のIDであることは別確認。
この変更はアカウント・トークンの新規作成や権限拡大を実行しない。

## 保存と結果不明

- policyは用途、依頼ID／依頼元、メンション方式、本文SHA256、固定2送信先を持つ。本文から任意の送信先・ID・名義を選べない。
- 両送信意図と配送束を最初の送信前に1回のatomic saveで保存する。計画中の例外でも片方だけが後続のerror saveへ混ざらない。
- 依頼は指示部屋の確定後にグループへ進む。報告は依頼元別にまとめ、2送信先の状態とtsを独立保存する。
- 短文・rich textの両方で、実応答の送信者、送信先、全文、メンション、照合印、tsを検査する。欠落・警告・相違は結果不明。
- `last_delivery_receipt` の一致した安全な情報だけをoutboxへ保存する。本文3000文字と既存の独立ヘッダー予算を保持する。
- タイムアウト・途中終了・不正返却は自動再送しない。許可済みbot読取経路の完全一致で照合し、履歴未発見だけを未送信の証拠にしない。
- 一方の成功を他方の成功へ流用しない。報告のseenは両方のreceipt確定後に一度だけ更新する。手動postedのts欠落や取消も両方成功とはしない。
- 旧outbox、seen、旧held、URL baselineを削除・拡張して過去報告を再生しない。state version2と旧readerのソースは維持し、追加記録は必要な場合だけ保存する。
- 片方への指示投稿後に原本が変わったら、残りは対象だけ保留し、別版を自動配信しない。

## 報告・受領の境界

`--status` の `dual_delivery` で送信先別の状態、依頼元照合待ち、文字／公式宛先を確認できる。
2部屋投稿、本人への通知・受領、実着手、作業完了、たかむねの完成確認は別判定。
完了報告はreports種別を維持し、新規指示・human wake・のあ起動へ変換しない。
あいす等の外部受信側の排他受付は本リポジトリから実証できない。同じIDの2通知を1依頼として扱えるかは実受領段階で確認する。
まむbridgeは新旧の配送証拠を読み分けるが、本人／あいすの応答成功を独立確認したとは扱わない。

## 検証・配備

`TMPDIR=/private/tmp python3 scripts/test_offline.py` は全socket生成・接続・名前解決を禁止する。
Macの `/var` と `/private/var` の一時path差を避けるため、実pathのTMPDIRで試験する。製品のpath検査を緩めない。
新規・混合宛先、本文3000文字、相手別メンション、部分成功、結果不明、原本改訂、再起動、手動resolve、旧state互換、まむ連携を検証する。

GitHubへの実装・マージとMacの配備は別工程。配備時は対象版／最新差分／既存worker・lock／STOPの状態を確認し、
最新state・logsを保全してからコードのみを更新する。既存.env・plist・予定・秘密値を勝手に変更しない。
旧版へ戻す場合も最新state/logsを巻き戻さず、dual-v2のqueued/sending/heldを旧版で処理しない。新規配送をSTOPで止めて照合する。
実投稿や保留試験を開発試験の代わりに追加しない。
